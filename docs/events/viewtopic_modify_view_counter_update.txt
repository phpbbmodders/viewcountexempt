The code at this spot is the same on 3.3.x and master, so the change

PURPOSE
=======
Let extensions decide whether a page view adds to a topic's view count
(and to the download counts of attachments shown inline on that page).

USE CASE
========
Board owners have asked for years for some views not to count:

- an admin setting up forums, checking permissions or editing many
  imported posts adds hundreds of views to topics nobody else has read;
- a topic author can push up the view count of their own topic just by
  reloading it.

The only answer today is to edit the condition in viewtopic.php by hand
and redo the edit after every phpBB update. Recent example (phpBB
3.3.19): https://www.phpbb.com/community/viewtopic.php?p=16140973#p16140973

phpbbmodders/viewcountexempt will use this event to skip the count for
users or groups given a "views do not count" permission, for topic
authors on their own topics, and for admins, each set in the ACP.

No existing event can do this. core.viewtopic_post_row_after and the
other viewtopic events fire before the counter update but cannot change
its condition. The only workarounds are changing $user->data
['session_page'] so the check thinks the topic was already viewed (which
other code may read later), or taking the view back off with a second
UPDATE afterwards (an extra query on every topic view, and racy).

VARIABLES
=========
- update_view_counters (bool, read/write) - whether to increase the
  topic view count and the attachment download counts
- update_count (array, read/write) - IDs of the attachments whose
  download count will be increased; a listener can change it to count
  topic views but not downloads
- forum_id (int, read-only) - forum ID
- topic_id (int, read-only) - topic ID
- topic_data (array, read-only) - topic data, including topic_poster
